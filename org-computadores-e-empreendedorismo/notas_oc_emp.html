Organização de Computadores — Módulo 1
Unidade 1 · Organização do Computador, Processador e Execução de Instruções

Um computador moderno segue a Arquitetura de Von Neumann: CPU, memória, dispositivos de E/S e barramento interligados. Programa e dados ficam na mesma memória.

CPU — Componentes principais
ULA — Unidade Lógica e Aritmética: faz operações (+, -, AND, OR…)
UC — Unidade de Controle: busca, decodifica e executa instruções
Registradores — memória ultrarrápida interna (PC, IR, ACC…)
Registradores importantes
PC — Program Counter: endereço da próxima instrução
IR — Instruction Register: instrução atual
MAR — Memory Address Register
MDR — Memory Data Register
ACC — Acumulador: resultado da ULA
Ciclo de Instrução (Fetch-Decode-Execute)
1. FETCH — PC → MAR → Memória → MDR → IR (busca a instrução) 2. DECODE — UC decodifica o opcode do IR (entende a instrução) 3. EXECUTE — UC aciona ULA/registradores (executa a instrução) 4. PC = PC+1 — aponta para a próxima instrução (incrementa PC) (repete infinitamente enquanto o computador estiver ligado)
Exemplo — Executando ADD R1, R2
1. Fetch: busca instrução da memória no endereço do PC.
2. Decode: UC identifica opcode ADD, operandos R1 e R2.
3. Execute: ULA soma R1 + R2, resultado vai para R1.
4. PC aponta para próxima instrução.
⚠ Pipeline
Técnica que executa várias instruções em paralelo, cada uma em fase diferente. Ex: enquanto instrução 2 é decodificada, instrução 3 já está sendo buscada. Aumenta throughput mas não reduz latência individual.
⚠ RISC vs CISC
RISC (ARM, MIPS): instruções simples, tamanho fixo, execução em 1 ciclo. Mais fácil de fazer pipeline. CISC (x86): instruções complexas, tamanho variável, mais próximas da linguagem de alto nível.
Unidade 2 · Hierarquia de Memórias

As memórias são organizadas em uma hierarquia: quanto mais rápida, menor e mais cara. O objetivo é equilibrar velocidade e custo.

Memória Cache

A cache guarda cópias de dados frequentemente usados da RAM. Baseia-se em dois princípios de localidade:

Localidade Temporal
Dado usado recentemente tende a ser usado novamente em breve. Ex: variável de loop — i é acessada muitas vezes.
Localidade Espacial
Dado próximo ao que foi acessado tende a ser acessado logo. Ex: elementos consecutivos de um array.
⚠ Cache Hit vs Miss
Hit: dado encontrado na cache → rápido. Miss: dado não está na cache → busca na RAM (lento) e traz para cache. Taxa de hit ≈ 95% em programas bem escritos.
Memória Virtual

Permite que processos usem mais memória do que a RAM física disponível, usando o disco como extensão. O SO gerencia a tabela de páginas para mapear endereços virtuais em físicos.

Exemplo — Paginação
Processo de 1GB em sistema com 512MB de RAM: SO mantém as páginas mais usadas na RAM e o restante no disco (swap). Quando uma página ausente é acessada → page fault → SO carrega do disco.
⚠ Page Fault
Ocorre quando a página acessada não está na RAM. O SO interrompe o processo, carrega a página do disco para a RAM e retoma. Muito frequente = thrashing — sistema passa mais tempo trocando páginas do que processando.
Exercícios Resolvidos
Exercício 1: Qual é o papel do PC (Program Counter)?
→ Guardar o endereço da próxima instrução a ser executada.
Após cada fetch, PC é incrementado automaticamente. Em desvios (if/for), PC recebe o endereço de destino do salto.
Exercício 2: Por que a cache funciona bem na prática?
→ Porque programas exibem localidade temporal e espacial — acessam repetidamente os mesmos dados e dados próximos.
Loops acessam a mesma variável várias vezes (temporal). Arrays são acessados sequencialmente (espacial). Isso garante alta taxa de hit na cache.

Linguagem Assembly

Assembly é a representação simbólica do código de máquina — cada instrução assembly corresponde a uma instrução de máquina. É convertido para binário pelo montador (assembler).

; Exemplo: soma de dois números em Assembly x86 section .data a dd 10 ; variável a = 10 b dd 20 ; variável b = 20 resultado dd 0 section .text mov eax, [a] ; carrega a em EAX add eax, [b] ; EAX = EAX + b mov [resultado], eax ; salva resultado ; if (a > b) em Assembly cmp eax, ebx ; compara a e b jg maior ; jump if greater → vai para 'maior' ; ... bloco else maior: ; ... bloco then
⚠ Importante
Assembly é dependente de arquitetura — código x86 não roda em ARM sem recompilação. C e Java abstraem isso: o compilador/JVM gera o código de máquina correto para cada arquitetura.

Exercícios Resolvidos
Exercício 3: Qual a diferença entre compilador e interpretador?
→ Compilador traduz tudo antes de executar (mais rápido na execução). Interpretador traduz e executa linha a linha (mais flexível, mais lento).
C é compilado: gcc gera executável binário otimizado. Python é interpretado: cada linha é traduzida e executada em tempo real. Java é híbrido: compila para bytecode, que a JVM interpreta/JIT-compila.
Exercício 4: No modo imediato, onde está o operando?
→ O valor está embutido na própria instrução — não precisa de acesso à memória.
ADD R1, #5 — o 5 vem direto da instrução. É o modo mais rápido pois evita acesso à memória, mas limita o tamanho do valor (cabe em poucos bits da instrução).
Organização de Computadores — Módulo 3 · Entrada/Saída e Arquiteturas Atuais
Unidade 1 · Dispositivos e Operações de E/S

A comunicação entre CPU e dispositivos de E/S é muito mais lenta que a CPU. Há três técnicas principais para gerenciar essa diferença:

Técnica E/SComo funcionaCPU fica bloqueada?Uso
E/S Programada (Polling)CPU fica em loop verificando se dispositivo terminouSim — fica em busy-waitSistemas simples/embarcados
E/S por InterrupçãoDispositivo avisa a CPU via IRQ quando terminaNão — CPU trabalha em outra coisaTeclado, mouse, rede
DMA (Direct Memory Access)Controlador DMA transfere dados sem envolver a CPUQuase não — só no início/fimDisco, placa de vídeo, áudio
Exemplo — Interrupção de Teclado
1. Usuário pressiona tecla. 2. Controlador de teclado gera IRQ. 3. CPU termina instrução atual e salva contexto. 4. CPU executa ISR (Interrupt Service Routine) — lê o dado do teclado. 5. CPU restaura contexto e continua o programa anterior.
Exemplo — DMA para leitura de disco
1. CPU configura DMA: endereço da memória destino, quantidade de bytes, endereço no disco. 2. DMA assume o barramento e transfere os dados diretamente para a RAM. 3. Ao terminar, DMA gera interrupção para avisar a CPU. CPU não ficou parada!
⚠ Barramento (Bus)
Canal compartilhado de comunicação. Barramento de dados: transporta os dados. Barramento de endereços: indica onde ler/escrever. Barramento de controle: sinais de leitura, escrita, interrupção. Largura do barramento de endereços define o espaço máximo endereçável.

Lei de Amdahl
O ganho de paralelismo é limitado pela fração serial do programa. Se 20% do código é serial, o máximo de speedup é 5× (1/0,2), independente de quantos núcleos você adicionar.
Exercícios Resolvidos
Exercício 5: Por que DMA é preferível à E/S programada para transferência de grandes volumes de dados?
→ DMA libera a CPU para outras tarefas durante a transferência. Polling desperdiça 100% da CPU esperando.
Numa leitura de 1GB do disco com polling, a CPU ficaria presa em loop por segundos. Com DMA, ela executa outros processos e recebe interrupção ao final da transferência.
Exercício 6: Por que ARM domina smartphones e x86 domina desktops?
→ ARM é mais eficiente energeticamente (bateria). x86 tem maior desempenho bruto com energia ilimitada.
RISC (ARM) executa instruções simples com menos transistores e menos calor. CISC (x86) tem instruções complexas que fazem mais por ciclo mas consomem mais energia.
Organização de Computadores — Módulo 4 · Sistemas Operacionais
Unidade 1 · Gerência de Processos: Processos, Threads, Multiprogramação e Escalonamento

O Sistema Operacional (SO) gerencia os recursos do hardware (CPU, memória, E/S) e fornece uma interface para os programas. Atua como intermediário entre hardware e aplicações.

Processo
Programa em execução com seu próprio espaço de memória, registradores e contexto. Processos são isolados entre si. Troca de contexto entre processos é custosa.
Thread
Linha de execução dentro de um processo. Threads do mesmo processo compartilham memória. Troca de contexto entre threads é mais leve. Ex: aba do Chrome = thread.
Estados de um Processo
Novo → Pronto → Executando → Bloqueado → Pronto → ... → Terminado Novo: processo criado, aguardando admissão Pronto: na fila, aguardando CPU Executando: com a CPU (só 1 por núcleo por vez) Bloqueado: aguardando E/S ou evento (libera a CPU) Terminado: encerrou a execução
Algoritmos de Escalonamento
AlgoritmoComo funcionaProblema
FCFS (First Come First Served)Ordem de chegada, sem preempçãoConvoy effect: processo longo bloqueia todos
SJF (Shortest Job First)Menor burst de CPU primeiroStarvation: processos longos nunca executam
Round RobinCada processo ganha um quantum de CPU, depois vai para o fim da filaMuita troca de contexto se quantum pequeno
PrioridadeProcesso com maior prioridade executa primeiroStarvation de baixa prioridade
Multilevel QueueFilas separadas por tipo de processoComplexidade de configuração
Exemplo — Round Robin quantum=4
Processos P1(burst=8), P2(burst=4), P3(burst=6). Execução: P1(4ms)→P2(4ms)→P3(4ms)→P1(4ms)→P3(2ms). Total: 18ms. P1 e P3 não ficam presos esperando P2 terminar.
⚠ Preempção
Algoritmos preemptivos (Round Robin, Prioridade preemptiva) podem interromper um processo no meio da execução. Não-preemptivos (FCFS, SJF) esperam o processo liberar a CPU voluntariamente.

TécnicaComo funcionaProblema

⚠ Fragmentação
Interna: espaço desperdiçado DENTRO do bloco alocado (bloco de 4KB para processo de 3KB → 1KB desperdiçado). Externa: espaço livre espalhado em pequenos fragmentos não contíguos — soma total seria suficiente, mas não contíguo.
Exercícios Resolvidos
Exercício 7: Qual a diferença entre processo e thread?
→ Processo tem memória própria e isolada. Threads compartilham a memória do processo pai.
Criar um processo é mais custoso (novo espaço de endereçamento). Thread é mais leve — ideal para paralelismo dentro do mesmo programa. Ex: servidor web cria uma thread por requisição, não um processo.
Exercício 8: Por que o Round Robin é mais justo que o FCFS?
→ Round Robin divide a CPU igualmente entre todos. FCFS pode deixar processos curtos esperando um processo longo terminar.
Com quantum de 100ms, cada processo tem no máximo 100ms por vez. No FCFS, se P1 tem burst de 10 segundos, P2 e P3 esperarão 10s mesmo que durem 1ms cada.
Empreendedorismo — Módulo 1 · Projetos, Ferramentas e Análises de Negócios
Unidade 1 · Levantamento de Ideias e Descoberta de Oportunidades

Empreendedorismo é o processo de identificar oportunidades, desenvolver ideias e criar valor — seja em uma startup ou dentro de uma empresa (intraempreendedorismo).

Design Thinking
Abordagem centrada no humano para resolver problemas. Etapas: Empatizar → Definir → Idear → Prototipar → Testar. Foco em entender o usuário antes de criar a solução.
Brainstorming
Geração livre de ideias em grupo sem julgamento inicial. Regras: quantidade sobre qualidade, nenhuma ideia é ruim, construa sobre ideias dos outros.
Análise SWOT
Strengths — Forças internas
Weaknesses — Fraquezas internas
Opportunities — Oportunidades externas
Threats — Ameaças externas
Pesquisa de Mercado
Coleta e análise de dados sobre clientes, concorrentes e mercado. Primária: pesquisa própria (entrevistas, surveys). Secundária: dados já existentes (relatórios, IBGE).
Exemplo — SWOT de um App de Delivery
Forças: equipe técnica, tecnologia própria. Fraquezas: sem capital para marketing, marca desconhecida. Oportunidades: crescimento do delivery pós-pandemia. Ameaças: iFood e Rappi consolidados no mercado.
Oportunidade vs Ideia
⚠ Diferença crucial
Ideia = pensamento criativo sem validação. Oportunidade = ideia que resolve um problema real para um mercado disposto a pagar. Empreendedor de sucesso valida se há oportunidade real antes de investir tempo e dinheiro.
Unidade 2 · Prototipagem de Ideias

Prototipar significa criar versões simplificadas do produto para testar hipóteses com o menor custo possível antes de desenvolver o produto completo.

Tipo de ProtótipoFidelidadeCustoObjetivo
Papel/WireframeBaixíssimaQuase zeroTestar fluxo e conceito
Mockup DigitalMédiaBaixoTestar interface visual
MVPFuncional mínimoMédioValidar valor com usuários reais
Protótipo FuncionalAltaAltoTeste completo antes do lançamento
⚠ MVP — Minimum Viable Product
Produto com o mínimo de funcionalidades que entrega valor real ao cliente. Objetivo: aprender o máximo com o mínimo de esforço. Lean Startup: Build → Measure → Learn. Evita construir algo que ninguém quer.
Exemplo — MVP do Airbnb
Os fundadores não construíram a plataforma inteira. Criaram um site simples, fotografaram o próprio apartamento e anunciaram. Ao conseguir hóspedes reais, validaram que havia demanda antes de investir no desenvolvimento completo.

Equity: investidor recebe % da empresa (Angel, VC). Não precisa devolver dinheiro, mas perde parte do controle. Dívida: empréstimo bancário — mantém controle total, mas precisa pagar juros e parcelas.
Exercícios Resolvidos
Exercício 9: Qual a diferença entre ideia e oportunidade de negócio?
→ Ideia é criativa mas não validada. Oportunidade é ideia que resolve problema real para mercado disposto a pagar.
"Aplicativo para passeios de unicórnio" é ideia. "Aplicativo que conecta donos de cães com passeadores" é oportunidade — problema real, mercado existente, disposição a pagar.
Exercício 10: O que é MVP e por que é importante?
→ Produto mínimo que entrega valor real. Valida hipóteses com mínimo investimento antes de construir tudo.
Startups falham porque constroem produtos completos sem validar demanda. O MVP permite aprender com usuários reais gastando pouco, e pivotar se necessário.

Unidade 1 · Criação de Startups e Plano de Negócios

Uma startup é uma empresa jovem em busca de um modelo de negócios escalável e repetível. Diferente de pequenas empresas tradicionais, startups buscam crescimento rápido e disrupção de mercado.

⚠ Plano de Negócios vs Canvas
Plano de negócios: documento detalhado (30-50 páginas), exigido por bancos. Canvas: 1 página visual e flexível — ideal para startups em fase de descoberta. Canvas primeiro, plano depois se necessário.
Unidade 2 · Inovação e Desenvolvimento de Produtos
Tipos de Inovação
Incremental: melhora produto existente (iPhone 15→16)
Radical: novo produto que muda o mercado (iPhone 1º)
Disruptiva: começa simples/barato, derruba líderes (Netflix vs Blockbuster)
De processo: nova forma de fazer o mesmo
Produto × Mercado Fit (PMF)
Momento em que o produto resolve muito bem um problema de um segmento de mercado. Indicadores: crescimento orgânico, retenção alta, NPS alto, clientes indicam outros. Antes do PMF: iterar. Após PMF: escalar.
Exemplo — Inovação Disruptiva: Uber
Começou com carros executivos (UberBLACK), não táxis. Mais caro que táxi, mas mais conveniente. Depois expandiu com UberX (mais barato). Disrupcíonou o transporte sem possuir um carro sequer.
Unidade 3 · Diferenciação e Segmentação de Mercado

Segmentação é dividir o mercado em grupos com características e necessidades similares. Permite focar recursos e criar mensagens mais eficazes.

Tipo de SegmentaçãoCritériosExemplo
GeográficaPaís, região, cidade, climaCasacos de inverno para Sul do Brasil
DemográficaIdade, renda, gênero, educaçãoProdutos premium para renda acima de R$10k
PsicográficaEstilo de vida, valores, personalidadeProdutos eco-friendly para consumidores conscientes
ComportamentalFrequência de uso, lealdade, ocasiãoDescontos para usuários frequentes
Estratégias de Diferenciação (Porter)
Liderança em Custo
Ser o mais barato do mercado. Exige eficiência operacional máxima. Ex: Shopee, Casas Bahia. Risco: guerra de preços.
Diferenciação
Oferecer algo único que justifique preço maior. Ex: Apple, Tesla. Risco: o diferencial pode ser copiado.
Foco/Nicho
Atender bem um segmento específico. Ex: Nubank (jovens desbancarizados), produtos veganos. Risco: nicho pode ser pequeno demais.
Blue Ocean
Criar mercado novo sem concorrência. Ex: Cirque du Soleil (não compete com circo nem teatro — criou novo mercado).
Exercícios Resolvidos
Exercício 11: Qual bloco do Canvas define como a empresa gera receita?
→ Fontes de Receita (Revenue Streams).
Ex: assinatura (Netflix), freemium (Spotify), comissão por venda (Airbnb), publicidade (Google). Um negócio pode ter múltiplas fontes de receita.
Exercício 12: Qual a diferença entre inovação incremental e disruptiva?
→ Incremental: melhora o existente. Disruptiva: cria novo mercado ou derruba líderes começando de baixo.
iPhone 15→16 é incremental (câmera melhor). Netflix vs Blockbuster é disruptiva — começou pior (sem lojas, sem posse do DVD) mas mais conveniente e barata, acabou eliminando o concorrente.
