Módulo 1 — Proposta do Projeto
Unidade 1 · Visão Geral de FPC e Definição de Requisitos

FPC é a disciplina integradora do curso — conecta os conhecimentos das outras disciplinas em um projeto real. O foco é desenvolver uma solução Dashboard completa: da proposta à entrega.

O que são Requisitos?

Requisitos descrevem o que o sistema deve fazer (funcionais) e como deve se comportar (não-funcionais). São a base de todo o desenvolvimento.

Requisitos Funcionais (RF)
O que o sistema faz. Funcionalidades visíveis ao usuário.

Ex: "O sistema deve exibir gráfico de vendas por mês", "Usuário deve poder filtrar por período".
Requisitos Não-Funcionais (RNF)
Como o sistema se comporta. Qualidades do sistema.

Ex: "O dashboard deve carregar em menos de 3 segundos", "Deve funcionar em dispositivos móveis".
Tipo de RNFDescriçãoExemplo no Dashboard
DesempenhoVelocidade de respostaGráficos carregam em <3s
UsabilidadeFacilidade de usoInterface intuitiva, responsiva
SegurançaProteção de dadosAutenticação, dados não expostos
DisponibilidadeUptime do sistemaDisponível 99% do tempo
ManutenibilidadeFacilidade de manutençãoCódigo documentado e modular
Como Levantar Requisitos
1 · Entrevista com o cliente/usuário
Pergunte: "O que você precisa ver no dashboard?", "Quais decisões você toma com esses dados?", "Com que frequência você usa?". Anote tudo.
2 · Observação / Análise do contexto
Observe como o usuário trabalha hoje. Quais planilhas usa? Quais relatórios gera manualmente? Esses são candidatos a automação no dashboard.
3 · Prototipagem rápida (wireframe)
Esboce a tela no papel ou no Figma. Mostre ao usuário e valide: "É isso que você imaginou?" Antes de codificar.
4 · Documentar e priorizar
Liste todos os requisitos. Priorize com MoSCoW: Must have (essencial), Should have (importante), Could have (desejável), Won't have (fora do escopo).
⚠ Escopo bem definido evita retrabalho
Um requisito vago como "o sistema deve ser rápido" gera conflito. Prefira: "O dashboard deve carregar os dados em menos de 3 segundos com conexão de 10 Mbps". Seja específico e mensurável.

Módulo 2 — Execução do Projeto · Dashboard
Unidade 1 · Implementação da Solução Dashboard

Um dashboard é uma interface visual que consolida dados e KPIs em um único painel, facilitando a tomada de decisão. Deve ser claro, objetivo e atualizado.

Elementos essenciais de um Dashboard
KPIs (Key Performance Indicators)
Métricas numéricas principais. Exibidas em destaque. Ex: Total de Vendas, Ticket Médio, Clientes Ativos, Meta Atingida (%).
Gráficos
Barras: comparar categorias.
Linhas: evolução no tempo.
Pizza/Donut: proporção do todo.
Scatter: correlação entre variáveis.
Filtros / Controles
Permitem ao usuário explorar os dados. Ex: seletor de período, dropdown de região, filtro por produto. Devem ser intuitivos.
Tabelas
Para dados detalhados onde o usuário precisa ver valores exatos. Use com moderação — prefira gráficos para visão geral.
Boas Práticas de Design de Dashboard
① Hierarquia visual — o mais importante primeiro
KPIs principais no topo, gráficos de detalhe abaixo. O olho do usuário vai do topo-esquerda para baixo-direita. Coloque o dado mais crítico nessa posição.
② Menos é mais — evite poluição visual
Cada gráfico deve responder uma pergunta. Se você não consegue dizer "esse gráfico mostra X", ele não deveria estar lá. Remova decorações desnecessárias.
③ Cores com propósito
Use verde para bom/positivo, vermelho para alerta/negativo, amarelo para atenção. Não use cores só para decorar — cada cor deve transmitir informação.
④ Responsividade
O dashboard deve funcionar em telas diferentes (desktop, tablet). Use layouts em grid flexível. Teste sempre em resoluções diferentes.
⑤ Dados em tempo real vs estático
Defina se os dados atualizam automaticamente (polling/websocket) ou manualmente (botão "atualizar"). Indique sempre a data/hora da última atualização.

Unidade 2 · Resultados da Solução Dashboard

A fase de resultados documenta e apresenta o que foi entregue. Inclui demonstração do sistema, análise dos dados exibidos e avaliação do cumprimento dos requisitos.

Como documentar os Resultados
1 · Demonstração funcional
Mostre o dashboard funcionando com dados reais ou de exemplo. Grave um vídeo ou tire capturas de tela de cada funcionalidade implementada.
2 · Rastreabilidade de requisitos
Para cada RF da proposta, mostre se foi implementado. Crie uma tabela: RF01 → Implementado / RF02 → Parcialmente / RF03 → Não implementado (justifique).
3 · Análise dos dados exibidos
Interprete o que os gráficos mostram. Ex: "O gráfico de vendas mostra pico em março, coincidindo com a campanha promocional". O dashboard deve gerar insight, não só exibir número.
4 · Limitações e trabalhos futuros
O que não foi feito e por quê? O que poderia ser melhorado? Ex: "A integração em tempo real não foi implementada por limitação de tempo — poderia ser feita com WebSocket".

FuncionalidadeDashboard carrega, filtra e exibe dados corretamente

Design / UXInterface clara, hierarquia visual, cores com propósito

Template de Requisito Funcional
RF01 — Exibir KPIs Principais Descrição: O sistema deve exibir na tela inicial os KPIs: total de vendas, ticket médio e meta atingida (%). Prioridade: Must Have Critério de aceite: KPIs visíveis ao abrir o dashboard, atualizados com os dados do período selecionado. RF02 — Filtrar por Período Descrição: O usuário deve poder selecionar um intervalo de datas para filtrar todos os dados exibidos no dashboard. Prioridade: Must Have Critério de aceite: Ao alterar o período, todos os gráficos e KPIs atualizam automaticamente.
